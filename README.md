# SL Flights · Автотесты

Проект для ДЗ по модулю 7 и итогового задания курса. **22 сценария** проверяют: вход, поиск рейсов, сортировку и бронирование в SL Flights v01. 
Стек: Java 21, Selenium WebDriver, JUnit 5, Gradle и Allure Report. При проектирование тестов использовался паттерн Page Object. 


## Запуск

**IntelliJ IDEA.** Откройте папку с `settings.gradle` как Gradle-проект. В **Settings → Build, Execution, Deployment → Build Tools → Gradle** задайте **Gradle JVM** JDK 21–25 и **Run tests using → Gradle**. В **Gradle → Tasks → verification** запустите `test`, задачу нужного браузера или `crossBrowserTest`. Для одного сценария нажмите ▶ рядом с методом класса, например `confirmsBookingWithEditedPassenger()` в [BookingTests.java](src/test/java/ru/qa/flights/tests/BookingTests.java).

**Терминал.** 
На macOS запустите `./run.sh prepare`
На Windows в PowerShell  `.\run.ps1 prepare`. 

Скрипт при необходимости загрузит JDK 21. Запуск без аргументов откроет меню. С установленным JDK работают `./gradlew` и `.\gradlew.bat`.

```bash
./run.sh test                                       # полный набор в Chrome
./run.sh test -Pbrowser=firefox -Psuite=smoke        # быстрая проверка в Firefox
./run.sh crossBrowserTest --continue                # Chrome, Firefox и Safari
```

`test` берёт браузер и набор из [config/test.properties](config/test.properties). Задачи `chromeTest`, `firefoxTest` и `safariTest` выбирают браузер. Драйверы Chrome и Firefox подбирает Selenium Manager. В Safari на macOS включите **Разработка → Разрешить удалённую автоматизацию**. Для запуска Safari с Windows задайте `safariRemoteUrl` узла Grid с macOS.

Allure сохраняет автономный отчёт в `reports/allure/index.html`, исходные результаты — в `reports/allure-results/`. Новый прогон очищает предыдущие результаты. Задача `allureReport` собирает отчёт и при падении проверок.

## Техники тест-дизайна

- **Классы эквивалентности.** Верные, неверные и пустые учётные данные, заблокированный пользователь, поиск с рейсами и без рейсов, валидные и невалидные данные пассажира.
- **Граничные значения.** Вчерашняя дата отклоняется, сегодняшняя допускает поиск. Дата берётся из часового пояса браузера.
- **Переходы состояний.** Вход, поиск, результаты, бронирование и возврат. Проверяем состояние формы, сохранение запроса и отмену несохранённых изменений.

## Сценарии

Быстрый набор `smoke` включает **SM-01, AUTH-01, SEARCH-01 и BOOK-01**.

| ID | Действие и ожидаемый результат | ТЗ |
| --- | --- | --- |
| SM-01 | Открыть форму входа. Оба поля принимают ввод, кнопка доступна | SR-01-01 |
| AUTH-01 | Войти с верными данными. Открывается поиск, в приветствии показано ФИО | SR-01-04, 05 |
| AUTH-02 | Ввести неверный пароль. Форма остаётся открытой и сообщает об ошибке учётных данных | BR-01-01, SR-01-02 |
| AUTH-03 | Отправить оба поля пустыми. Форма запрашивает логин и пароль | BR-01-03 |
| AUTH-04 | Ввести верный пароль заблокированного пользователя. Вход отклонён с сообщением о блокировке | SR-01-03 |
| AUTH-05 | Нажать Logout. Форма входа очищается, дата поиска сбрасывается на сегодня | SR-01-06, 07 |
| SEARCH-01 | Найти рейсы Москва → Лондон на понедельник. Маршрут, дата, время, цена и счётчик совпадают с расписанием | BR-02-04, SR-03-01, 03 |
| SEARCH-02 | Удалить дату и отправить форму. Появляется запрос даты вылета | BR-02-02 |
| SEARCH-03 | Указать вчерашнюю дату. Поиск отклоняется с сообщением о прошедшей дате | SR-02-04 |
| SEARCH-04 | Найти Казань → Париж на понедельник. Счётчик равен нулю, таблица сообщает об отсутствии рейсов | SR-03-03, 04 |
| SEARCH-05 | Нажать «Новый поиск». Оба города и дата восстановлены | SR-03-07 |
| SEARCH-06 | Открыть поиск и отправить текущую дату. Дата предзаполнена, поиск открывает результаты | SR-02-03, 04, 06 |
| RESULT-01 | Отсортировать по времени в обе стороны. Порядок соответствует времени вылета | SR-03-05, 06 |
| RESULT-02 | Отсортировать по цене в обе стороны. Порядок соответствует стоимости | SR-03-05, 06 |
| RESULT-03 | Сменить сортировку пустой выдачи. Сообщение об отсутствии рейсов остаётся | SR-03-04, 06 |
| BOOK-01 | Выбрать рейс, отредактировать данные пассажира и завершить регистрацию. Подтверждение содержит выбранный рейс и введённые данные | SR-04-01, 03, 04, 08 |
| BOOK-02 | Ввести буквы в паспорт. Бронирование отклонено с ошибкой формата паспорта | SR-04-07 |
| BOOK-03 | Ввести ФИО латиницей. Бронирование отклонено с ошибкой формата ФИО | SR-04-06 |
| BOOK-04 | Ввести email без `@`. Форма отклоняет бронирование и сообщает об ошибке email | BR-04-05 |
| BOOK-05 | Очистить телефон. Форма отклоняет бронирование и запрашивает заполнение всех полей | SR-04-05 |
| BOOK-06 | Ввести телефон из букв. Форма должна отклонить бронирование | BR-04-05 |
| BOOK-07 | Изменить ФИО и вернуться к списку. При повторном открытии рейса подставляются исходные данные | SR-04-09 |
